# Boolean query filter parsing

The shared query schemas interpret the exact strings `"true"` and `"false"` as
their corresponding Boolean values. Typed `true` and `false` remain supported
for callers that parse objects directly. Previously, generic Boolean coercion
interpreted the nonempty string `"false"` as `true`, reversing explicit filters.

| Schema                   | Field      | Omitted value                      |
| ------------------------ | ---------- | ---------------------------------- |
| `ProjectQuerySchema`     | `archived` | `false`                            |
| `TaskQuerySchema`        | `archived` | `false`                            |
| `FileQuerySchema`        | `trashed`  | `false`                            |
| `WikiCommentQuerySchema` | `resolved` | `undefined` (no resolution filter) |

Empty strings, numeric values/strings, null, arrays including repeated query
parameters, objects, whitespace and case variants are invalid. The four existing
backend routes use these schemas through `validateQuery`, which returns HTTP 400
for invalid values and forwards parsed Boolean values to the handler. No stored
data or migration changes are needed.

```sh
pnpm --dir packages/shared test
pnpm --dir packages/backend exec node --import tsx --test tests/query-boolean-validation.test.mjs
pnpm test
pnpm lint
pnpm build
```

The shared test command builds the package before testing its compiled exports.
Its four table-driven regression cases retain default and optional behavior,
test both typed and string Boolean values, and reject malformed inputs. Four
additional Fastify cases exercise the actual HTTP query parser and validation
middleware, checking routed value types and that rejected values stop before
the handler. These parsing tests use no database and do not claim to test
database results or route authorization.

The root unit command requires the shared test script through direct workspace
directory dispatch. It builds shared exports once through that script, then
runs CI policy tests, the existing optional backend unit script, and the required
frontend suite. Backend integration dispatch remains required. Disposable
workspace tests execute the actual root scripts with valid non-target scripts,
then independently verify each required suite rejects a missing script, runs a
success marker, and propagates a failing script's nonzero exit.

This fixes SHR-001's Boolean query contract. Calendar dates, ordered ranges,
array/depth limits and broader C07 contracts remain separate work.
