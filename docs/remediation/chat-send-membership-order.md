# Chat send admission and membership ordering

A send transaction rechecks the current workspace role and joined-channel membership while holding their admission rows until commit or rollback. Existing ADMIN/MEMBER send policy remains; VIEWER cannot send, and public-channel discovery does not confer send permission. Workspace removal retains DM membership/history, but those rows do not replace current workspace membership.

Admission order is Workspace KEY SHARE, ChatChannel NO KEY UPDATE, WorkspaceMember SHARE, then ChatChannelMember KEY SHARE. Workspace/channel deletion starts at the parent, avoiding a new inverse cascade order. Workspace KEY SHARE remains compatible with the existing workspace membership mutex; sends to unrelated channels do not acquire a workspace-wide exclusive lock. Role updates and member deletion conflict with the relevant admission row. The earlier committed admission either finishes first or observes the preceding removal/demotion and refuses without send writes. Response delivery can occur after a later membership change; committed message history is not withdrawn by this contract.

The private acquisition bounds cumulative admission work by a decreasing five-second budget and preserves stricter server statement/lock limits. Prisma's inherited acquisition/transaction options are not widened. Bounded admission lock cancellation is a retryable conflict; existing transaction/deadlock handling still rolls back partial writes. No automatic retry is added. User-deletion cascade cycles can still be resolved by PostgreSQL aborting one transaction; that existing retryable outcome does not commit a partial message/outbox.

Matching keyed replay uses the same admitted transaction and preserves the original stored DTO, including replay after archive. New sends to archived channels remain refused. A cross-channel author/key uniqueness conflict rolls back, then re-admits before returning an existing keyed result or request mismatch. Channel timestamp, message, thread subscription and delivery outbox writes remain atomic; request keys/hashes remain omitted from public message DTOs. Post-commit delivery and current-recipient filtering are unchanged.

The regression fixture uses real PostgreSQL row waits and only its own short ordinary records. A channel-row gate measures revocation winning before admission; an owned outbox gate measures an admitted send holding membership until commit. Temporary trigger functions target exact owned data and are removed after all operations settle. The user-cascade case measures rollback classification, not account/session policy. Direct-service tests do not claim HTTP/WebSocket transport or operational/load acceptance. The existing route and atomicity fixture, current full suite and independent review remain complementary gates.
