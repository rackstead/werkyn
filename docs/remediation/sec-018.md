# Workspace static upload roots

Static upload authorization and file resolution use the same workspace uploads root.
Previously an encoded traversal under a workspace where the caller was a member could
read known paths elsewhere in storage, including another tenant's uploads. The handler
now validates the workspace path segment, denies escapes before streaming, and supplies
the narrow authorized root to Fastify's file server.

With a migrated disposable PostgreSQL database, run:

```sh
TEST_DATABASE_URL=<disposable-url> pnpm --filter @pm/backend exec node --import tsx --test tests/integration/static-upload-root.test.mjs
```

Real HTTP/PostgreSQL tests reproduce the original foreign read and cover encoded slash
variants, a sibling directory, legitimate nested bytes, authentication, foreign membership,
and current membership revocation. They use isolated storage and remove their UUID fixtures.

This fixes SEC-018's tenant-root escape. Uploaded active-content response policy is a
separate SEC-017 fix; storage symlinks remain a separate lifecycle/trust-policy gate.
