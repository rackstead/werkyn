# Production signing keys and database defaults

Compose requires independently generated JWT, cookie, and PostgreSQL secrets instead
of starting production with published values. Production startup rejects short signing
keys and the shipped sample prefixes. PostgreSQL's development port binds to loopback.
Local HTTP remains supported; remote HTTPS needs the documented secure-cookie and origin
settings in the root environment template.

Run `pnpm --filter @pm/backend test` for startup rejection, legitimate configuration,
old-key token rejection, and Compose interpolation/listener regressions. Compose checks
require Docker Compose and report an explicit skip when it is unavailable. These tests
resolve configuration without starting the application or accessing real user data.

For existing installations, follow the README rotation instructions and preserve volumes.
A disposable PostgreSQL 16 drill confirmed that restarting with a changed initialization
password preserves data and leaves the existing role unchanged; explicit SQL role rotation
then accepts the new password and rejects the old one while preserving the seeded row.
No existing deployment's secrets or database were changed by this remediation.

Length and sample-prefix checks cannot establish randomness. Operators must generate the
separate secrets and rotate credentials for existing deployments. General environment
validation, non-root containers, and full deployment/restore gates remain separate work.
