# Uploaded content response isolation

Uploaded HTML, JavaScript, XML, SVG and unknown file types are returned as
`application/octet-stream` attachments. Static workspace, avatar, general-upload
and legacy-upload routes apply the response policy after the static server has
selected its MIME headers. Successful GET, HEAD and range responses receive
`sandbox; default-src 'none'; base-uri 'none'; form-action 'none'`, `nosniff`,
and `private, no-store`. The existing workspace-root authorization remains intact.

Drive downloads apply the same isolation policy. Explicit `inline=true` previews
are limited to the listed raster-image, PDF, audio and video MIME types; active,
unknown and missing MIME types remain attachments. Ordinary downloads remain
attachments. Thumbnails retain their raster type and use private caching.
Attachment and public-share downloads already force octet-stream attachments;
their existing response behavior is regression tested without changing their
separate authorization policy.

Before this change, application-origin uploaded documents and script files could
receive the application's script privileges. Historical local browser evidence
established that defect. Current regressions use benign markers and generated
passive media, with no account-access or credential-extraction fixtures.

```sh
pnpm --filter @pm/shared build
TEST_DATABASE_URL="$AUDIT_DATABASE_URL" pnpm --filter @pm/backend exec node --import tsx --test tests/integration/untrusted-content.test.mjs
```

Use an explicitly selected, migrated disposable PostgreSQL database. Tests create
UUID-scoped records and temporary storage, verify all four static roots, MIME
normalization, HEAD/range responses, unchanged PNG/PDF/WAV/WebM bytes, Drive
previews/downloads, thumbnails and the existing download-only siblings. The tiny
media fixtures are generated locally; the WebM records four 32px canvas frames.
Each test run removes its own records and files.

A benign Chromium native-reader smoke also verifies uploaded-script rejection,
HTML downloads, raster/audio/video decoding, and static/Drive PDF rendering both
top-level and in a visible iframe. This checks response compatibility; full
frontend flows and other browser engines remain separate release gates.

This scope does not close file/share/attachment access policy, public-share
password enforcement, storage symlink/lifecycle/resource limits, or general
credential/cache revocation. Browser rendering and download/subresource behavior
must also be checked against the reviewed commit; byte/MIME tests alone do not
establish that a particular browser's PDF reader renders correctly.
