# Browser-bound, single-use OIDC state

An OIDC attempt now requires its signed, HttpOnly, host-only browser cookie as
well as the URL state. The callback verifies the signature and compares the
64-character random state in constant time before reading or consuming server
state. A missing, invalid or different attempt's cookie cannot consume the pending
attempt or exchange a code. Existing identity/linking and token-signature policy
from SEC-005 remains unchanged.

Each attempt has its own cookie for parallel tabs. Cookies last ten minutes, use
SameSite=Lax for the IdP's top-level redirect, inherit the configured Secure flag,
and cover `/api/auth/oidc`. Initiation prunes the signed attempt cookies supplied
by that request to retain four before setting a new one. Concurrent initiations
can temporarily produce more cookies until a later initiation prunes them; this
is not a global database admission limit. A callback clears only its own cookie.
In-flight attempts begun before this binding change must restart sign-in.

A conditional PostgreSQL delete elects one state claimant. Expired and replayed
attempts cannot exchange a code, and expiry is checked again after a claim waits
on the database. A properly bound provider-error callback consumes its attempt
without reflecting the provider's description. Malformed query values fail with
a controlled redirect. Handler redirects use no-store, return URLs remain local,
and callbacks have a thirty-per-minute IP limit. The actual authorization-response
issuer is forwarded to the installed OIDC validator rather than synthesized.

Tests use a loopback disposable signed IdP, actual Fastify cookie handling and
PostgreSQL fixtures. They cover normal/no-hint/legacy identity login, cookie
attributes and signing, missing/invalid/foreign bindings, replay/expiry, separate
tabs, provider errors, query/return URL validation, issuer forwarding and rate
limits. Simultaneous HTTP callbacks exchange once. Two deliberately overlapping
real database reads elect one conditional claimant, and a real row lock held past
expiry verifies that delayed consumption is rejected. Existing SEC-005 test cases
are preserved; only their cookie round-trip fixture changes.

With an explicitly selected, migrated disposable database:

```sh
TEST_DATABASE_URL="$AUDIT_DATABASE_URL" pnpm --filter @pm/backend exec node --import tsx --test --test-concurrency=1 tests/integration/oidc-state.test.mjs tests/integration/oidc-identity.test.mjs
```

Real Dex/upstream-provider browser flows and deployed cross-origin/HTTPS cookie
compatibility remain release gates. Abandoned-state cleanup/global admission,
general transport/logging policy and session/credential revocation remain separate
work. No schema, dependency, identity-policy or deployment change is included.
