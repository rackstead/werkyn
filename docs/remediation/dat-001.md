# Project child-resource scope

Custom-field values, task templates, and recurring-task configurations must belong
to the project authorized by the request URL. Knowing a child resource ID does not
grant permission through an unrelated project or workspace.

Template reads, updates, and deletes, and recurring-configuration updates and
deletes now resolve the resource using both its ID and the authorized project ID.
Their final update/delete predicates retain that project constraint. Template
instantiation and recurrence creation also resolve the referenced template in the
same project. Setting or clearing a custom-field value validates both the task and
field against that project before any value, activity log, or event is written.

Valid same-project requests retain their existing response formats and workspace
role requirements. A mismatched child returns 404; role checks may reject it with
403 first. Denials disclose no child metadata and create no writes or broadcasts.

The regression suite uses the actual Fastify authentication, authorization,
validation, controller, service, and PostgreSQL paths. It checks ADMIN, MEMBER,
and VIEWER behavior across two projects in one workspace and another workspace;
template GET/PATCH/DELETE/instantiation, recurrence mutation/creation, and all
task/field/project combinations for setting and clearing values. It compares
database snapshots and captured broadcasts on denial and exercises legitimate
CRUD operations.

Run against an explicitly designated, migrated disposable PostgreSQL database:

```bash
pnpm --filter @pm/shared build
TEST_DATABASE_URL="$AUDIT_DATABASE_URL" pnpm --filter @pm/backend test:integration
```

The integration command also retains the existing API-key tests and executes test
files sequentially in test mode. Fixtures use random IDs and clean up their own
records and temporary storage. Never use an application database for these tests.

Project-member restrictions, uniform task edit/assignment policy, referenced
status/assignee/label integrity, scheduler durability, and concurrent ordering
remain separate work. This change does not claim to enforce those boundaries.
The inspected application has no supported task or custom-field transfer across
projects; a future transfer implementation must preserve the validated relation
through its transaction.
