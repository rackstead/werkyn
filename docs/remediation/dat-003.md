# Project membership admission and current content reads

Project access requires current membership in its workspace. Current workspace
ADMINs can access every project in that workspace. MEMBERs and VIEWERs also need
an explicit ProjectMember row. An administrator of another workspace has no
override, and a stale ProjectMember row cannot replace workspace membership.
Existing route role requirements and task assignment/edit rules remain in force.

The same admission check now covers project routes and resources derived from
tasks, typed comments/subtasks, and both project references in time entries.
Supplied parent/task contexts must agree. Resolving a comment only as a comment
and a subtask only as a subtask prevents IDs that collide across tables from
selecting a different authorization context. Workspace activity and project counts
follow project visibility; dashboard, search, and assigned-task visibility retain
their existing membership filters.

Time creation and updates authorize the actual referenced task's project and the
independent project reference before writing or returning their titles/names.
Lists, reports, and CSV exports check both nullable references against current
membership and the request workspace, including legacy mismatched relations.
Projectless entries remain available. Reports/CSV remain workspace-ADMIN-only;
ADMINs retain visibility of same-workspace projects without explicit project
membership. This check does not enforce task/project consistency when both
references are independently accessible; that is a separate integrity requirement.

New project notifications filter recipients against current project/workspace
rights before storage or delivery. Task-only payloads, including due-date
reminders, resolve the task's actual project; a supplied project hint cannot
replace that parent. Existing historical notifications require separate revocation
handling.

Realtime project subscription admission uses the same policy. Explicit project
member removal clears that user's current-process project subscriptions after the
transaction commits and invalidates pending subscription authorization reads.
It also denies later HTTP requests, time reads/mutations,
and new subscriptions. This does not provide general socket session expiry,
workspace removal/role-change revocation, or cross-process invalidation; those
remain separate realtime work. Already authorized responses in flight cannot be
retroactively withdrawn.

Regression coverage uses actual Fastify/JWT/Prisma/PostgreSQL, isolated UUID
fixtures, and temporary storage. It verifies outsider MEMBER/VIEWER and foreign
ADMIN denials across project/task/derived route families with unchanged database
snapshots and no broadcasts; positive member/ADMIN operations; typed ID collisions;
workspace discovery/activity counts; recipient filtering and actual comment
delivery; stale workspace membership; explicit project removal, including an
authorization read overlapping the real removal transaction; and time mutation,
list, report, CSV, and membership-revocation carriers. Socket-shaped fixtures
exercise the actual subscription/broadcast functions, not network WebSocket
transport.

corrupt cross-project joins), historical notification revocation, broader realtime
revocation, and browser validation. These code changes alone do not close those
release gates.
