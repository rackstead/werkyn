# Account and share password hashing

New account registration/change/reset and file/wiki share passwords use Argon2id v19 with19MiB memory, time2, parallelism1,16-byte random salt and32-byte output. The same helper governs all callers. Current composition and128UTF16 account/100UTF16 share schema limits remain. The helper bounds UTF8 input to512bytes and refuses illformed UTF16 rather than replacing it; it never normalizes or truncates passwords. Valid non-BMP text, literal replacement characters and NUL remain exact.

Stored Argon2 hashes accept only this exact canonical format/cost/salt/output tuple. Unsupported, malformed or excessive-cost hashes fail ordinary verification before native work. A maximum of two Argon2/bcrypt jobs may be active in one process; no waiting native queue is accepted. Excess work gets a fixed503 and may be retried by the caller. Each permit remains held until its actual native Promise settles; abandoning a request observer cannot release it. This conservative bound is not production capacity acceptance.

Legacy bcrypt $2a/$2b cost04..12 hashes accept candidates of at most72UTF8bytes. Longer candidates fail ordinary verification and require the existing account reset route or a share-manager password update. Old bcrypt discarded suffix information: a matching72-byte prefix remains indistinguishable from a longer original. No login rehash, live hash rewrite, original-byte recovery or deployment migration is claimed. Existing legacy fixture bytes remain immutable; raw bcrypt compatibility is tested separately from this deliberate application restriction.

Password/share authorization, CAS, reset/session logic, share grant revision binding and response omission stay unchanged. Backups already omit user accounts/passwords and public shares; no backup format change is introduced. Operational native failures and busy work return fixed errors without exposing the stored hash, password or native details. Native Node floor/musl and real transport evidence remain explicit validation gates; source/engine metadata alone does not prove them.
