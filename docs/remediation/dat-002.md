# DAT-002: scoped chat authorization and private recipients

Every chat HTTP request first verifies the caller's current workspace membership
and role. Channel resources must belong to that URL workspace; message resources
resolve through their actual channel before access. PRIVATE channels and DMs
require channel membership, including for workspace administrators. Public
channels remain discoverable/readable by workspace members; sending still requires
joining the channel and an ADMIN or MEMBER workspace role.

This boundary covers channel/member/message/thread/read/typing/reaction/pin/
bookmark/subscription/archive/search routes. DM creation and adding channel members
validate every recipient against current workspace membership before writing.
Search and retained bookmarks filter inaccessible private content. Private channel
lifecycle events stay on the channel feed, while public creation/deletion events
continue to reach workspace subscribers. Mentions, DM notifications and thread
reply events include only current channel members who still belong to the workspace.

Before this fix, a caller could supply an authorized own workspace in the URL while
reading another workspace's known private-channel messages; the message-list route
returned the foreign body. The regression suite uses disposable PostgreSQL fixtures
to verify ADMIN/MEMBER/VIEWER against foreign PUBLIC/PRIVATE/DM resources and local
private nonmembership, with database and realtime-event snapshots proving denial
has no side effects. It also exercises legitimate public joining/sending, private
message operations, channel/workspace search, DM reuse and notification recipients.

Run after migrating an explicitly selected disposable database:

```bash
pnpm --filter @pm/shared build
cd packages/backend
TEST_DATABASE_URL=<disposable-postgresql-url> node --import tsx --test --test-concurrency=1 tests/integration/chat-authorization.test.mjs
```

HTTP middleware protects the current route/controller call graph; future non-HTTP
service callers must supply equivalent authorization. This change does not close
DAT-006's cached WebSocket revocation/expiry boundary or DAT-014's message/outbox
atomicity boundary. Those require separate fixes and concurrency tests. Realtime
regressions here use socket-shaped clients through the actual authentication,
subscription and broadcast service, not browser/network WebSocket transport.
