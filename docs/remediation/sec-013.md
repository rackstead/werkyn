# File read grants and current access lists

File reads now use current workspace membership plus ownership, direct/group team
membership or an explicit member share. Explicit shares are independent read-only
grants: they permit active file metadata, content, thumbnails, starring and archives.
A folder grant includes active descendants that retain the same owner and effective
team scope. It exposes no private ancestor and does not follow foreign, inactive or
malformed team roots. Multiple grants remain independent when one is revoked.

A recipient can copy a readable file into a destination where they separately have
write access. Reading a source grants no permission to rename, move, trash, delete,
reshare it, inspect recipient lists, create folders or upload into a shared folder.
Workspace VIEWER remains read-only. Ownership and actual team membership retain their
existing write rights for MEMBER/ADMIN; an admin's authority stays in that workspace.

Search, folder navigation, starred files, shared-with/by-me and share-status queries
apply the same read predicate before returning metadata. Search and shared-with-me
filter before their existing pagination. Shared-with-me lists direct share anchors;
descendants are reached through folder navigation/search. Personal root listing stays
personal. Trash metadata remains available through owner/team/admin authority, while
explicit grants do not permit trashed-source reads or restore. Removing a share or
membership takes effect on subsequent reads; stale stars remain removable by their user.

File shares confer no team membership. Team folder lists and roster/detail routes
require actual direct/group membership or current workspace ADMIN, so an explicit
recipient reads the shared file tree through file routes without roster emails or
group details. Team and group relations must remain in the requested workspace.

Public-link credential lists require write authority on the requested source and
link creator/current workspace ADMIN authority. Another writer cannot obtain a mixed
bundle's token through one of its files. Nested file metadata also requires current
read access. Managers can still disable/delete stale links, with unreadable source
metadata omitted. Shared-by-me and status results carry no bundle tokens. Public
password grants, credential revisions, hash-free DTOs and token entropy remain SEC-001.


Tests cover explicit/direct/group/ancestor grants, independent revocation, current
roles, list pagination, malformed legacy scopes, manager credentials, roster boundaries
and denial without row, storage, notification or event changes. The manager suite's
stale-source expectation now checks revocation success with source metadata filtered;
its manager authorization remains intact.

Attachments (SEC-006), backup assets, legacy data repair/constraints, graph-writer
serialization (B01), durable storage cleanup and browser/release gates remain separate.
Permission checks do not cancel an already streaming response. Shared-by-me still has
its existing unbounded pagination behavior, and recursive grant-query performance has
not been measured; this change claims no performance improvement.
