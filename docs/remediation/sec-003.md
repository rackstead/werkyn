# File workspace and destination authorization

File access now binds each resource to the requested workspace and reads the actor's
current database membership and role before applying admin, owner or team permissions.
An admin role in one workspace gives no authority over another workspace's files.
Existing direct and group team permissions remain supported; a group, team record and
its active folder root must belong to the file workspace. VIEWER cannot write.

Upload, create, copy and move resolve the actual active destination folder before any
storage write or row mutation. Team-only destinations resolve to their team root;
explicit team and parent references must agree. Writes into another user's personal
folder by a same-workspace admin retain that folder's owner. A move validates the
collected subtree and updates its owner/team scope in one database transaction.

Member and public sharing validate every source before inserting any share rows.
Archive selections and expanded children are checked before opening content streams.
Legacy public-share entries cannot list or download foreign-workspace or trashed files.
Share lists and indicators also discard foreign-workspace and trashed source records.
Owner restore and deletion of trashed files remain available with current write access.

Run the intended-permission regression fixtures against migrated disposable PostgreSQL:

```sh
TEST_DATABASE_URL=<disposable-url> pnpm --filter @pm/backend exec node --import tsx --test tests/integration/file-tenant-boundary.test.mjs
```

Coverage includes admin/member/viewer and removed memberships, ordinary personal and
team operations, direct/group revocation, invalid and mismatched destinations, atomic
share validation, public legacy records, and denial before storage/content/events.
An injected database failure verifies subtree transaction rollback.

This is the SEC-003 extraction. Share-link manager permissions (SEC-002), explicit-share
read grants and consistent list predicates (SEC-013), attachments (SEC-006), public
password grants (SEC-001), and backup assets remain separate work. The existing short
public tokens and link update/delete policy are unchanged here. Graph guards and the
subtree transaction do not serialize concurrent graph writers: B01/SEC-014, historical
data repair/constraints, storage lifecycle, browser flows and performance remain open.
Permission checks apply to subsequent operations; they do not cancel content already
streaming when membership changes.
