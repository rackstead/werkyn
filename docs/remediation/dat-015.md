# Bookmark pagination query validation

The bookmark list validates its cursor and page size before calling the service.
Explicit numeric limit strings become numbers; limit must be an integer from
1 through 100. Omitting it preserves the existing default of 20. Invalid values
return HTTP 400 rather than reaching Prisma with a string page size.

The existing authentication, current workspace membership and bookmark
user/channel/workspace filters remain unchanged. Valid cursor requests preserve
the existing descending bookmark order and nextCursor contract.

Run the real HTTP/PostgreSQL regressions on a migrated disposable database:

```sh
pnpm --filter @pm/shared build
TEST_DATABASE_URL=<disposable-url> pnpm --dir packages/backend exec node --import tsx --test tests/integration/bookmark-pagination.test.mjs
```

Four cases cover consecutive one-item pages, the default and maximum page sizes,
invalid and repeated parameters without persisted changes, and retained
user/channel/workspace authorization. The bounded fixtures contain 24 visible
bookmarks and separate private-channel, foreign-workspace and peer-user records.

This fixes DAT-015's bookmark query contract. Cursor ordering under concurrent
writes, frontend pagination, chat idempotency and broader C07/B08/P02 work remain
separate.
